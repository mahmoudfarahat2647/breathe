group ("Off" / "Wind down") that will live inside the existing "Show advanced options"
disclosure. This is one slice of GitHub issue #33 (Ramp T1). You are NOT wiring it into
the page and you will NOT commit — the orchestrator does both.

## What to change

### 1. New file `src/presentation/ramp-picker.tsx`

Model it exactly on `src/presentation/goal-picker.tsx` (same `"use client"` header, same import
style, same `<Button>` usage).

- Props: `type RampPickerProps = { selectedRamp: Ramp; onSelect: (ramp: Ramp) => void };`
  Import `Ramp` and `RAMP_CATALOG` from `@/domain/ramp`.
- Render:
  - Outer `<div className="ramp-picker">`
  - `<span className="ramp-picker-label label-tier">Ramp</span>`
  - `<div className="ramp-options" role="group" aria-label="Ramp">` containing two chip buttons:
    - "Off"       — selected when `selectedRamp === null`; `onClick={() => onSelect(null)}`
    - "Wind down" — selected when `selectedRamp === "wind-down"`; `onClick={() => onSelect("wind-down")}`
      (use `RAMP_CATALOG["wind-down"].name` for the label text)
  - Each chip: `<Button type="button" size="breathe" variant={selected ? "breathePrimary" : "breatheSecondary"} aria-pressed={selected}>`
  - After the options div, a description line:
    `<p className="default-hint">{selectedRamp ? RAMP_CATALOG[selectedRamp].description : "No ramp — durations stay as you set them."}</p>`

Keep it a pure presentational component — no `useState`, no effAects, no domain logic beyond
reading `RAMP_CATALOG`.

### 2. `src/presentation/index.ts`

Add `export { RampPicker } from "./ramp-picker";` next to the existing `GoalPicker` export
(match the surrounding export style — check whether the file re-exports types too).

### 3. `src/app/globals.css`

The chip visual treatment is currently scoped behind the `.mv-deck` ancestor, e.g.:

    .mv-deck .breathe-btn { ... }
    .mv-deck .breathe-btn[aria-checked="true"],
    .mv-deck .breathe-btn[aria-pressed="true"] { ... }
    .mv-deck .breathe-btn[aria-checked="true"]::after,
    .mv-deck .breathe-btn[aria-pressed="true"]::after { ... }

The RampPicker renders inside `.mv-advanced` (NOT inside `.mv-deck`), so it gets none of that.
**Extend each of those selector lists** to also match the ramp chips by adding a
`.mv-advanced .ramp-options .breathe-btn` variant to every selector in that group (including the
`.mv-deck .goal-options` layout rule → also `.mv-advanced .ramp-options`, and the `::after` dot
rules). Do not delete or restyle the existing `.mv-deck ...` selectors — only add the parallel
`.mv-advanced .ramp-options ...` selector to each comma list.

Then add, near the `/* goal chips */` block:

    .ramp-picker {
      width: 100%;
      display: flex;
      flex-direction: column;
      gap: 10px;
    }
    .ramp-options {
      display: flex;
      flex-wrap: wrap;
      gap: 8px;
    }

And extend the existing full-width grid rule so the ramp row spans all columns of the
`.duration-fields` grid — change:

    .duration-fields .default-row,
    .duration-fields .default-hint {
      grid-column: 1 / -1;
    }

to also list `.duration-fields .ramp-picker`.

Do NOT introduce any new CSS custom properties / design tokens — reuse the existing
`--mv-*` vars the goal chips already use. Do NOT add any `transition` to `.ramp-picker`,
`.ramp-options`, or `.default-hint`.
